### 카메라·표시 장치

- **모듈:** FMC LCD-Camera Module.
- **카메라:** 1080p/30FPS, PL 16bit 병렬 입력. UM p.28·예제 RTL.
- **신호:** PCLK 148.5MHz, XDC 주기 6.734ns, 예제 I/O는 LVCMOS33.
- **초기화:** `tp2825B.c` I²C 설정 제공. 정확한 센서 모델은 실물 확인 필요.
- **영상 경로:** BT.1120 해독 → 영역 자르기 → YUV422→RGB → DDR → LCD.
- **LCD:** 7인치·800×480·최대 60FPS·RGB888 병렬. UM p.28·31.
- **터치:** 최대 5점·I²C 제어. UM p.28·31.
- **핀맵:** UM p.40~59, 회로도, `FLC_FPGA_Design.xdc` 확보.

### 개발 도구·실행 환경

- **LCD 예제:** Vivado/Vitis 2022.2, bare-metal C·XSA 제공.
- **Windows 안내:** LCD p.4는 Vivado 2022.1 이상 요구.
- **기타 예제:** PL은 주로 2020.1, PS는 주로 2021.1.
- **PetaLinux 튜토리얼:** 2022.2.
- **AI 실습:** Ubuntu 18.04·Vitis-AI 1.2.1. SDK 설명은 PetaLinux 2020.1.
- **실행 전 확인:** 실제 OS·BSP·device tree·툴체인·드라이버·IP 라이선스.

### 제공 LCD 예제의 자원 기록

| 자원 | 사용 / 전체 |
|---|---:|
| LUT | 18,668 / 53,200 |
| FF | 23,909 / 106,400 |
| BRAM tile | 19.5 / 140 |
| DSP | 29 / 220 |

- 배치 보고서 기준. 현재 CNN 통합 설계의 자원량은 미측정.
- 제공 타이밍 보고서 WNS: **+0.470ns**.
- 입·출력 지연 미지정 포트 존재. CNN 통합 후 제약·타이밍 재검증 필요.

## 3. 실보드 확인 순서

### 모델·리비전·구성품

1) 메인보드 앞뒤의 제품명·`REV`/`VER` 기록.
2) FPGA 윗면을 문서의 `XC7Z020-1CLG484C`와 대조.
3) FMC 모듈·카메라 뒷면의 모델·리비전·라벨 기록.
4) 메인보드 앞뒤·FPGA·FMC·카메라 라벨 촬영.
5) 아래 구성품의 보유 여부 확인. 구매 구성에 따라 제공품은 다를 수 있음.

- 메인보드·FMC LCD/카메라 모듈·전원 어댑터.
- USB-B(JTAG)·Mini-USB(UART) 케이블.
- USB-OTG 어댑터·SD 카드.

**확인 기준**

- FPGA 표기가 가려져 있으면 JTAG로 디바이스부터 확인. PCB 리비전은 별도 기록.
- `TP2825B` 코드만으로 카메라 센서 모델을 확정하지 않음.
- **참고:** UM p.6~7·10·30.

### 전원

1) 제공 어댑터의 전압·전류·극성을 보드 사양과 대조.
2) 전원을 끈 상태에서 FMC 결합·케이블 상태 확인.
3) CN11에 전원 연결 후 SW6 켜기.
4) 상태 LED 확인.

- **Power Good LD13:** 켜지면 전원 상태 확인.
- **DONE LD12:** PL 설정 완료 표시. 전원 상태와 구분.
- **참고:** UM p.11·13.

### JTAG 인식

1) 전원을 끄고 SW7을 JTAG 모드로 설정.
2) PC ↔ CN12를 USB-B 케이블로 연결 후 전원 켜기.
3) Vivado에서 `Open Hardware Manager → Open Target → Auto Connect` 선택.
4) 검출된 디바이스명·화면 기록.

- **정상:** Zynq-7020 디바이스 검출.
- **미인식:** CN12·데이터 케이블·케이블 드라이버 확인.
- **참고:** UM p.14~15, PL LED 예제 p.16~17.

**SW7 설정 — 실물의 번호와 `ON` 표시 기준**

| 모드 | 1번 | 2번 | 3번 | 4번 |
|---|---|---|---|---|
| JTAG | OFF | OFF | OFF | OFF |
| SD | ON | ON | OFF | OFF |

모드 변경은 전원을 끈 상태에서 수행. 근거: UM p.14~15 도해.

### UART·ARM 실행

1) PC ↔ CN10을 Mini-USB 케이블로 연결.
2) Windows 장치 관리자 `포트(COM 및 LPT)`에서 새 COM 번호 확인.
3) Tera Term 등에서 해당 COM을 열고 아래 통신 설정 적용.
4) Vitis에서 제공 UART 예제를 빌드·실행해 메시지 확인.

```text
Baud rate: 115200
Data:      8 bit
Parity:    None
Stop:      1 bit
Flow:      None
```

- **정상:** `Hello World` 출력. SD 부팅 시에는 읽을 수 있는 부팅 로그로도 확인 가능.
- **COM 없음:** CN10·USB-UART 드라이버 확인. 미인식 장치의 하드웨어 ID 기록.
- **글자 깨짐:** baud 설정 확인. COM은 한 프로그램에서만 열기.
- **출력 없음:** JTAG 모드에서는 ARM 프로그램 실행 여부 확인.
- **참고:** UART 예제 p.26~28.

### 카메라·LCD — SD 없이 JTAG로 실행

1) LCD 예제의 Vivado/Vitis 2022.2 구성 준비.
2) 하드웨어 빌드 후 XSA 내보내기.
3) Vitis에서 해당 XSA와 제공 C 소스로 애플리케이션 빌드.
4) `Xilinx → Program Device`로 PL bitstream 다운로드.
5) 애플리케이션의 `Run As → Launch Hardware`로 ARM 프로그램 실행.
6) 손·종이를 움직이거나 렌즈를 가려 LCD 반응 확인.

- **정상:** 실제 카메라 영상 갱신. 색상·화면 깨짐·정지 여부 확인.
- **기록:** 짧은 동작 영상·UART 로그.
- **다운로드 조건:** bitstream·ARM 프로그램은 같은 하드웨어 구성 사용.
- **재실행:** 전원을 껐다 켜면 PC에서 다시 다운로드.
- **참고:** LCD p.43~51은 빌드, p.52~54는 다운로드·실행.

### 처리 해상도

1) 센서 입력·DDR 저장 영상·LCD 표시 해상도를 각각 기록.
2) 전체 시야를 축소할지, 일부 영역을 잘라 처리할지 결정.
3) 전처리 입력 해상도 확정 후 최종 합성셋 생성.

| 구간 | 제공 예제 |
|---|---|
| 카메라 입력 | 1920×1080 |
| DDR 프레임 | 잘라낸 800×480 RGB, `main.c` 설정 |
| LCD 표시 | 800×480 |
| 프로젝트 전처리 입력 | 640×480 잠정 |

**LCD 해상도와 전처리 입력 해상도는 별도로 결정.**

## 4. SD가 있을 때의 부팅 확인

### 준비·부팅

1) 수령한 SD에 정상 데모가 있으면 그대로 먼저 실행.
2) 파일 변경 전 기존 내용을 PC에 보관.
3) 새로 준비한다면 아래 폴더의 파일을 같은 세트로 복사.
4) 전원을 끄고 SD·FMC·UART 연결, SW7을 SD 모드로 설정.
5) UART 로그 저장을 시작한 뒤 전원 켜기.

```text
3. AI Tutorial/
  2. MNIST AI Tutorial/
    3. MNIST Tutorial Booting Image/
```

- **SD 부팅 파티션 루트:** `BOOT.BIN`, `boot.scr`, `image.ub`.
- **함께 복사:** `libs/`·폰트·실행 파일·`start.sh` 등 폴더 내용 전체.
- **파일 구성:** 다른 예제의 부팅 파일과 혼합하지 않음.
- **정상:** U-Boot·Linux 로그 진행 후 로그인 프롬프트 또는 데모 표시.
- **계정:** 실제 이미지의 로그인 안내 사용.

### Linux 정보·데모 실행

1) 로그인 후 아래 명령으로 커널·메모리·SD 마운트 위치 기록.
2) 자동 실행되지 않으면 SD의 `start.sh` 내용 확인.
3) 실제 마운트 위치와 스크립트의 참조 경로·파일 대조.
4) 경로를 맞춘 뒤 해당 폴더에서 `sh ./start.sh` 실행.

```sh
uname -a
head -n 5 /proc/meminfo
mount | grep mmc
```

- **메모리:** 예약 영역 때문에 사용 가능 메모리는 물리 512MB보다 작을 수 있음.
- **경로 차이:** 설명서는 `/media/card`, 실제 스크립트는 `/media/sd-mmcblk0p1` 참조.
- **로그 없음:** SW7·UART·SD 파일 위치 확인.
- **부팅 중 멈춤:** 마지막 오류·전체 로그 보관.
- **영상 확인:** LCD 백라이트 점등과 실제 카메라 영상 갱신을 구분.

## 5. 예제 적용 시 주의

**영상·모델**

- 제공 영상 예제는 영역 자르기 사용. 전체 화면 축소 여부는 별도 결정.
- 제공 MNIST는 고정 ROI를 DPU로 분류하는 데모. MNIST p.32 참고.
- 카메라·LCD·부팅 경로를 참고하되, 현재 CNN의 다중 숫자 성능은 별도 평가.

**프로젝트·도구**

- LCD Tcl은 2022.2 요구. XPR에는 제작자 PC의 절대 경로 존재.
- 소스 재연결·BD 재생성 후 로컬 빌드 확인 필요.
- BRAM 예제 `6. Block Memory Test Design.zip`의 part는 `xc7a75tfgg484-1`.
- 보드용 part로 수정 후 BRAM IP 재검증 필요.

**문서·설정 불일치**

- 영상 형식: UM p.33은 `BT.1156`, LCD p.9·RTL은 `BT.1120` 표기.
- DDR: 회로도는 MT41K, LCD Tcl은 `MT41J128M16 HA-15E` 설정.
- 실물·부팅·캡처로 일치 여부 확인.
