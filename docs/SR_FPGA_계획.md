## 2. 문제와 범위

- **입력·출력:** 단일 RGB 이미지 `[1, 3, H, W]` → `[1, 3, 2H, 2W]`.
- **복원 조건:** Bicubic ×2 축소 LR과 HR 쌍. 상류 학습 프로젝트와 동일 조건 유지.
- **구현:** 기존 프로젝트 방향대로 Verilog 직접 구현. ARM은 제어·데이터 입출력 담당.
- **시작 범위:** 고정 크기 정지 이미지의 입력·복원·결과 회수부터 완성.
- **확장:** 보드 검증 후 카메라·LCD 시연 검토.
- **평가 구분:** 정해진 축소 조건의 정량 평가와 실제 카메라 시연을 구분.

### 전환 이유와 한계

- 학습 → 정수화 → 하드웨어 구현의 연결이 명확함.
- 보간·float 모델·FPGA 결과를 같은 영역에서 비교 가능.
- 합성곱·데이터 재사용·라인 버퍼·스트리밍을 설계 주제로 삼을 수 있음.
- FPGA SR 자체는 기존 연구가 있음. 차별점은 직접 설계한 모델의 화질·처리 시간·자원 관계를 실측하는 데 둠.
- 작은 파라미터 수만으로 빠른 처리가 보장되지 않음. 입력 크기별 MAC 수·활성 메모리·전송량 확인 필요.

## 3. 모델 선택과 하드웨어 제약

1) 상류 저장소에서 레퍼런스·설계 후보 검토.
2) 학습 전, 후보별 지원 연산·연산량·중간 결과 저장량 계산.
3) 소규모 학습과 정수화 예비 실험으로 복원 품질·구현 가능성 확인.
4) 구현할 모델의 구조·가중치·입출력 규칙·버전 고정.

- **출발 후보:** 저해상도 합성곱 → 출력 합성곱 → PixelShuffle ×2의 ESPCN 계열 검토.
- **초기 연산 후보:** 작은 합성곱·ReLU·PixelShuffle. 채널 수·블록 수·잔차 연결은 검토 후 결정.
- **PixelShuffle:** RGB ×2에서는 12개 출력 채널을 3채널·가로세로 2배로 재배열.
- **구조 선택 기준:** GPU 속도 외에 FPGA의 병렬도·메모리 접근·버퍼·제어 비용도 고려.
- **정밀도:** INT8·INT16 또는 혼합 정밀도를 검토하되, 화질 측정 전 확정하지 않음.

**연산량 예시 — 확정 모델 아님**

- 3×3 합성곱 `3→16→16→12` + PixelShuffle ×2.
- LR 픽셀당 MAC: `3×16×9 + 16×16×9 + 16×12×9 = 4,464`.
- 640×360 입력은 약 **1.03G MAC/장**. 메모리·제어 비용은 별도.
- 상류 GPU 벤치마크 크기·속도를 FPGA 목표로 그대로 적용하지 않음.

## 4. 데이터와 모델 인계

상류 [실험 계획][training-plan]의 원본 단위 분할을 유지.

| 구분 | 구성 | 용도 |
|---|---|---|
| train | DIV2K 공식 train 중 720장 | 상류 모델 학습 |
| val | DIV2K 공식 train 중 80장 | 구조·학습 설정·정수화 설정 선택 |
| 최종 평가 | DIV2K 공식 validation 100장 | 설정 고정 후 비교 |

- 위 표는 프로젝트 용도 분할. DIV2K 공식 test와 구분.
- 분할 ID·시드는 상류에서 확정한 기록을 사용. 여기서 다시 나누지 않음.
- 양자화 보정은 train에서 선정하고 최종 평가 데이터는 조정에 사용하지 않음.
- RGB 모델을 Y 채널 모델로 임의 변경하지 않음. 변경 시 상류 학습 조건부터 함께 수정.

**인계받을 항목**

- 모델 소스·설정·체크포인트·커밋·파일 해시.
- RGB 순서·값 범위·정규화·출력값 처리 규칙.
- 층별 커널·stride·padding·bias·활성화·PixelShuffle 순서.
- LR·HR 대응 파일과 고정 검증 입력, float 출력·층별 기준값.
- PSNR·SSIM의 채널·경계 제외·값 범위·집계 규칙.

## 5. 보드와 처리 구조

- **보드:** Libertron AI Starter Kit v2.1, Zynq-7020. [보드 조사](보드조사.md) 참조.
- **문서상 자원:** LUT 53,200·FF 106,400·BRAM tile 140·DSP 220·DDR3 기본 512MB.
- **실물 확인:** 리비전·전원·JTAG·UART·카메라·LCD 동작은 수령 후 검증.
- **초기 실행:** SD가 없으면 JTAG로 PL·ARM 프로그램 다운로드.
- **영상 예제:** 카메라 1920×1080 입력에서 800×480 영역을 잘라 DDR·LCD로 전달.
- **해상도:** LCD 해상도·전처리 입력·SR 출력 크기를 별도로 결정.

**구현 시 결정할 항목**

- 공유 MAC과 층별 스트리밍 중 구조 선택, 병렬도·클록.
- 라인 버퍼·타일 처리·DDR 중간 결과 저장·데이터 재사용.
- AXI 데이터 폭·픽셀 배치·경계 padding·프레임 제어.
- 출력 저장·PC 회수·LCD 표시 방식, ARM↔PL 전송·캐시 동기화.
- 영상 경로 사용량을 제외한 가용 자원과 목표 입력 크기·처리 시간.

## 6. 검증과 비교

| 검증 | 확인할 내용 |
|---|---|
| float 기준 | Bicubic·레퍼런스·설계 모델의 PSNR·SSIM·확대 결과 |
| 정수화 | float 대비 화질 변화·층별 범위·반올림·포화·출력 오차 |
| RTL | 고정 입력의 층별 정수값·최종 출력과 PC 정수 기준 일치 |
| 보드 | ARM·PL 전송과 출력 일치, 반복 실행·경계·프레임 처리 |
| 성능 | 모델 계산과 전송 포함 전체 시간을 각각 측정 |
| 자원 | LUT·FF·BRAM·DSP·클록·WNS, 전력은 측정/추정 구분 |

- 최종 품질 비교는 같은 LR·HR·출력 후처리·평가 규칙 사용.
- ARM 소프트웨어와 비교할 때 같은 정수 모델·입력 사용.
- GPU FP32 시간은 상류의 비교 결과로 활용. 보드 전체 시간과 측정 범위 구분.
- 목표 PSNR 손실·처리 시간·해상도는 예비 실험 후 확정. 현재 수치 약속 없음.
