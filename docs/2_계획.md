# 계획 — 실시간 손글씨 숫자열 판독기

완료한 일은 [개발기록](1_개발기록.md), 실행 방법은 [README](../README.md).

## 1. 목표

- **만들 것:** Zynq-7020 보드 카메라에 비친 손글씨 숫자열을 실시간 판독. CNN은 직접 작성한 Verilog로 PL에서 실행
- **주제 선정 근거:** LeNet의 원래 용도(수표·우편번호 숫자열 판독)를 FPGA로 재현. 숫자 N개 → 추론 N회라 가속기가 필요해짐
- **최소 목표:** 화면 중앙 ROI의 숫자 1개 분류 (N = 1). 숫자열 판독은 이 위에 쌓음
- **결과물:** 보드 시연·영상, 발표 자료, 보고서, GitHub 소스

## 2. 어필 포인트

| 축 | 내용 |
|---|---|
| 설계 | HLS·DPU 없이 Verilog 직접 작성. batch 처리·zero-skip 포함 |
| 검증 | Python 정수 reference와 bit-exact 일치 (층별 golden trace), 파형 근거 |
| 성능 | ARM 단독 대비 처리량(digits/s), 숫자 개수 N별 fps |
| 설계 공간 | MAC 병렬도 P = 8/16/32/64별 자원·성능 그래프 |
| 효율 | zero-skip 전후 cycle·전력(SAIF 추정) |

## 3. 시스템 구조

```text
camera → 축소·grayscale → 이진화 → CCL(숫자 후보 박스) → 필터·정렬 → crop별 28×28 정규화   [ARM]
       → CNN batch 추론 N회                                                                [PL]
       → 숫자열 조립 → LCD 표시 (박스·숫자·숫자열)                                            [ARM]
```

- **PL 직접 설계:** CNN 가속기 ([구조](3_가속기구조.md))
- **PL 표준 IP:** PS7, AXI, BRAM, 영상 frame buffer, Clock Wizard
- **ARM:** 카메라·LCD 초기화, 전처리·CCL, 가속기 제어, 숫자열 조립, 표시
- **판독 규칙:** 잉크 덩어리 하나 = 숫자 후보 하나. 크기·종횡비·화면 경계로 잡티 제외, 줄 구분 → 왼쪽부터 정렬 → 넓은 간격은 띄어쓰기. N_max 초과 시 큰 덩어리부터
- **시연 조건:** 흰 종이, 검은 펜, 고정 거리
- **확장:** ARM의 CCL이 병목으로 측정되면 PL 스트리밍 회로로 이전

## 4. 확정된 설계

| 대상 | 내용 | 문서 |
|---|---|---|
| 모델 | LeNet 계열 2-Conv CNN, 26,698 파라미터, float test 99.04% | [개발기록 2장](1_개발기록.md#2-mnist-cnn-학습-p1) |
| 정수 규격 | signed INT8, 누산기 24bit, 재양자화 M 16bit + shift, INT8 test 99.04% | [정수 규격](4_정수규격.md) |
| 가속기 구조 | 공유 MAC 배열 P = 8, Pool 결합, 재양자화 1개, AXI-Lite + AXI BRAM | [가속기 구조](3_가속기구조.md) |

**재학습 조건** (생기면 v2로 따로 저장, 이후 스크립트로 전부 재생성)
- 보드 카메라의 실제 손글씨 판독이 저조 → 증강 보강 (획 굵기·흐림)
- 잡티가 필터로 걸러지지 않음 → "숫자 아님" class 추가

| 단계 | 내용 | 결과 |
|---|---|---|

**보드 도착 후** (10/19~25 도착 예상 → 발표 12월 초 가정, 약 6주)

| 단계 | 내용 | 완료 기준 | 예상 기간 |
|---|---|---|---|
| P4b | RTL 단위 모듈 + testbench (PE → 후처리 → 주소 생성기 → 메모리 → FSM → AXI·top) | testbench 전부 PASS | 1주 |
| P5 | CNN 코어 통합 + batch 모드 (dense·P = 8 기준선) | golden mismatch 0, 100MHz timing | 1~1.5주 |
| P6 | 보드 bring-up, ARM baseline 측정, 판독 영역 해상도·N_max 확정 (P4b·P5와 병행) | 예제로 카메라·LCD 동작 | 병행 |
| P7 | PS-PL 결합, MNIST test 10,000장 보드 실행 | 보드 출력 = 정수 reference | 0.5주 |
| P8 | 단일 ROI 카메라 시연 (최소 목표) | 실시간 분류 안정 동작 | 0.5주 |
| P9 | 숫자열 판독 (CCL·정렬·batch) | N_max개 30fps | 1주 |
| P10 | zero-skip, 병렬도 P 비교, ARM 대비 처리량, 전력 | 비교 그래프 완성 | 1주 |
| P11 | 시연 영상, 발표 자료, 보고서 | | 0.5주 |

- **P5 순서:** dense 기준선을 먼저 mismatch 0으로 완성 → zero-skip·병렬도 확장은 그 뒤 변형으로
- **역할 분담:** 보드 도착 후 정함. 나누기 좋은 단위: 가속기 RTL(P4b·P5) / 보드·영상 경로(P6·P8) / ARM 전처리·숫자열(P9)
- **보드 도착 전 선택 작업:** 브라우저 시제품에 실제 손글씨 사진 테스트, Vitis의 ARM 컴파일러로 최소 standalone 빌드 확인

## 6. 검증·평가

| 단계 | 기준 |
|---|---|
| 단위 RTL | testbench 자동 비교 PASS + 핵심 파형 캡처 |
| 전체 RTL | golden trace와 층별 mismatch 0, 모든 실행 모드 |

| 보드 정량 | MNIST test 10,000장 → 정수 reference와 일치 |
| 숫자열 | 직접 만든 숫자열 이미지·영상의 문자열 정확도 (평가셋은 P9 전에 구성) |

| 지표 | 목표 | 현재 |
|---|---|---|
| float 정확도 | 99% 이상 | ✅ 99.04% |
