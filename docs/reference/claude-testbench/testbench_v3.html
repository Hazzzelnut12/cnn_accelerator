MNIST 모델 테스트벤치

학습한 float32 가중치(v1)를 브라우저에서 그대로 계산함 (정수화 전). 보드에 올릴 숫자열 판독 과정과 가속기 구조를 미리 검증하는 용도.

이 탭의 상태

숫자열 판독·단일 숫자 탭은 학습한 float32 가중치로 브라우저에서 계산하는 소프트웨어 구현임. 아래 구조도는 Zynq-7020 PL에 Verilog로 구현할 정수 가속기의 설계 초안이고, RTL은 아직 없음. 수치는 모델 크기에서 계산한 값이며 측정값이 아님.

브라우저 판독 · float32 소프트웨어 · 동작함 PL 가속기 · 설계 초안 · RTL 미구현 float 모델 MNIST test 99.04% (INT8·보드 정확도 아님) INT8 정확도 · 미검증 클록 100 MHz · 미검증 자원량 · 미검증 처리 시간 · 미검증

블록 구조도 (P4a 초안 v2)

블록을 누르면 아래 설명 카드로 이동함. 번호는 카드 번호와 같음. 실선은 데이터(비트 폭 표시), 보라 점선은 제어, 파랑은 ARM과 PL 사이 연결.

배치 원리
  • 위쪽 줄 = 제어 (2~4): 무엇을, 언제 계산할지 정함. 데이터 값은 다루지 않음
  • 가운데 = 저장과 공급 (5~8): 매 cycle 입력 x 8b 1개와 weight 64b word 1개(8b × 8)를 꺼내 줌
  • 오른쪽 가운데 = 계산 (9): 곱셈·32b 누산을 하는 유일한 곳
  • 아래 = 후처리와 되돌림 (10~13): 32b 누산값을 보관 → bias·ReLU → 8b로 줄여 버퍼로 되돌림. 데이터가 층마다 이 고리를 한 바퀴씩 돎
  • FC2만 다른 출구 (14, 15): ReLU·재양자화 없이 32b 점수로 argmax와 출력 버퍼에 감

정수화 사양 · 검증 전

INT8 weight·활성값은 목표 사양임. 정수 reference로 정확도를 비교하기 전까지 아래 항목은 확정이 아님. 99.04%는 float 모델의 MNIST test 기록이고 INT8 정확도나 보드 정확도가 아님.

데이터 공급과 처리량

P = 8에서 PE 8개가 매 cycle 일하려면 입력 x 8b 1개와 weight 8개(64b word 1개)가 매 cycle 같이 도착해야 함. BRAM은 주소를 넣고 1~2 cycle 뒤에 데이터가 나오므로, 주소 생성기가 낸 first/last·lane_en·padding 0 표시도 같은 cycle 수만큼 늦춰 데이터와 맞춰야 함.

후처리 병목과 부분 결과 저장
  • 결과 보관 레지스터: 누산이 끝나면 MAC은 바로 다음 묶음을 누산해 누산기를 덮어씀. 그래서 끝난 8개 값을 32b × 8 레지스터로 옮겨 두고 1개씩 후처리함.
  • 재양자화기 1개로 충분한지 (검증 항목): 8개를 1개/cycle로 처리하면 8 cycle. 다음 묶음 누산은 Conv2 72, FC1 784 cycle이라 여유가 크지만 Conv1은 9 cycle이라 여유가 1 cycle뿐임. 후처리가 매 cycle 1개를 받지 못하면 valid/ready 핸드셰이크로 MAC을 멈추거나 보관 레지스터를 2단으로 둠. RTL 시뮬레이션으로 확인.
  • Conv·Pool 결합의 부분 결과: 주소 생성 순서를 "채널 묶음 → pool 창 → 창 안 2×2 네 점 → 항"으로 두면, 한 창의 네 점이 연달아 나옴. 그래서 부분 결과는 채널별 최댓값 8b × 8 레지스터면 됨. 네 번째 점 값이 들어오는 순간 그 채널 최댓값을 Feature 버퍼에 씀. 행 순서로 계산하면 행 버퍼가 따로 필요함.

완료 조건 (RTL 전에 확정)
  • 층 전환: 마지막 MAC 항이 끝난 것만으로 넘어가지 않음. 결과 보관 → bias·ReLU → 재양자화 → MaxPool 파이프라인이 비고, 그 층의 마지막 Feature 버퍼 쓰기가 끝나야 다음 층 시작
  • crop 완료: FC2 점수 10개와 예측이 출력 슬롯에 모두 저장된 뒤
  • batch done: N번째 crop의 출력 저장이 끝난 뒤 busy = 0, done = 1, IRQ
  • 입력 반납: 마지막 실제 읽기(BRAM 읽기 지연 포함)가 끝난 뒤
  • 잘못된 명령 (초안): busy 중 start는 무시하고 오류 비트. busy 중 clear는 미정(중단 후 초기화 또는 무시). 이미 준비·계산 중인 버퍼에 BUF_READY를 다시 쓰면 무시하고 오류 비트. N이 1~16 밖이면 시작하지 않고 오류 비트
N = 16 처리 순서
  1. 초기화: CTRL.clear → 두 버퍼 쓰기 가능, done = 0, 출력 슬롯 무효
  2. 첫 두 장: crop 0 → A, crop 1 → B를 쓰고 각각 BUF_READY
  3. 시작: N(1~16)을 쓰고 CTRL.start → busy = 1
  4. 소비: PL이 crop i를 버퍼 (i mod 2)에서 계산. Conv1의 마지막 입력 읽기가 끝나면 그 버퍼가 쓰기 가능이 됨 (STATUS로 확인)
  5. 재사용: ARM이 반납된 버퍼에 crop i+2를 쓰고 BUF_READY. PL은 crop i의 FC2를 끝내고 다음 버퍼가 입력 준비면 바로, 아니면 기다림
  6. 결과: crop i의 FC2 점수 32b × 10과 예측을 출력 슬롯 i에 저장. 저장이 끝나야 crop i 완료
  7. 종료: N번째 crop의 출력 저장이 끝나면 busy = 0, done = 1, IRQ. ARM이 슬롯 N개를 읽고 done을 지운 뒤 다음 batch

Conv2 출력 한 점이 만들어지는 과정

채널 0~7, pool 창 하나를 예로 듦. 괄호 안은 블록 번호.

  1. FSM이 "Conv2, 채널 묶음 0(채널 0~7), pool 창 하나의 첫 점"을 주소 생성기에 지시 (3 → 4)
  2. 주소 생성기가 입력 항 72개(입력 채널 8 × 3×3)를 1 cycle에 하나씩 냄. 각각 Pool1 주소와 weight word 주소가 됨 (4)
  3. BRAM 읽기 지연 뒤 x 8b 1개가 PE 8개에 동시에, weight 64b word가 lane마다 8b로 들어감. first/last 표시도 같은 만큼 늦춰서 도착 (6, 7, 8)
  4. PE마다 x × w(16b)를 32b 누산기에 더함. 72 cycle 뒤 8개 완성 → 결과 보관 레지스터로 옮기고 다음 점 누산을 바로 시작 (9 → 10)
  5. 보관된 8개를 1개/cycle로 bias 덧셈(32b) → ReLU → 재양자화(8b). 8 cycle이라 다음 점의 72 cycle 안에 끝남 (11, 12)
  6. MaxPool 레지스터가 채널별 최댓값을 갱신. 창의 네 번째 점이면 최댓값을 Feature 버퍼의 Pool2 자리에 씀 (13 → 6)
  7. 채널 묶음 1(채널 8~15)로 반복. 마지막 창의 후처리와 Pool2 쓰기까지 끝나면 FC1로 넘어감 (3)
  8. FC1은 MaxPool 없이 8b로 저장. FC2는 묶음 2개(출력 8개 + 2개, lane 2~7 끔)로 32b 점수를 만들어 argmax와 출력 버퍼로 (14, 15)

블록별 설명

결정 사항

상태: 초안 = 구조 선택만 함, 미검증 = 측정·시뮬레이션 필요.

남은 검증 항목

  1. INT8 정수 reference의 MNIST test 정확도 (float 99.04%와 비교)
  2. 층별 실제 누산 범위(bias 포함) → 32b에 들어가는지, 줄일 수 있는지
  3. 정수화 규칙 확정: signed/unsigned, scale, zero-point, bias, 반올림, 포화, FC2 점수 scale
  4. 재양자화 곱의 폭과 구현(DSP 수·LUT), 1개/cycle 처리량, 결과 보관 레지스터·valid/ready 필요 여부 (합성·RTL 시뮬레이션, 특히 Conv1)
  5. 정수 예측과 float 예측의 일치율 (동점 규칙 포함)
  6. 층 전환·done이 마지막 메모리 쓰기 뒤에 일어나는지, 잘못된 명령 처리 (시뮬레이션)
  7. BRAM 개수·포트 폭·읽기 지연 정렬 (합성·시뮬레이션)
  8. 이중 버퍼 소유권: ARM이 계산 중인 버퍼를 덮어쓰지 않는지 (시뮬레이션)
  9. 100 MHz 타이밍(WNS), LUT·FF·DSP·BRAM 사용량 (합성)
  10. crop 하나·16개 처리 시간과 ARM 전처리 시간 (보드 측정)
